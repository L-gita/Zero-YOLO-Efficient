# 零-DCE 去马赛克：台阶、颗粒版、极端暗光 —— 思维导图与要点

> 用途：给自己以后复习用。一句话版本：**马赛克不是"我们变糊了"，而是"暗部本来就没几档信息，被增强曲线放大成了平台+硬边界"；颗粒版的原则是"只处理确定是噪声的部分，不制造新的色块，把剩下的台阶打散到看不见"。**

## 一、思维导图（文字版，可逐层展开）

```text
暗部马赛克 / 颗粒版
├─ ① 为什么会马赛克
│  ├─ 8-bit 量化：暗部实际只用到 18~37 个灰度档（126 那张只用 25 档）
│  ├─ 增强曲线放大：暗区斜率最大（126 实测放大 5.8 倍）
│  ├─ 台阶 × 放大 = 平台 + 硬边界 → 视觉上的"块"
│  ├─ 色度噪声被一起放大：3.6~7.5 倍
│  ├─ JPEG 8×8 块：只在低质量 JPEG / 4:2:0 下出现
│  └─ 平台边界被下游当成"边缘" → 干扰识别与抓取
│
├─ ② 我们的六个手段（一一对应上面六个成因）
│  ├─ 亮度降噪 luma_denoise：NLM 只作用 Y，结果与原图按 20% 混合
│  ├─ 去块 deblock：仅当块效应 > 1.03，且只平滑"边界两侧差<12"的弱阶
│  ├─ 阴影补偿 shadow_lift：输入均值<15 时暗部抬 4 级（找回变暗）
│  ├─ 近黑限增益 limit_dark_gain：<3 全用中性抬亮，3~12 羽化，>12 不动
│  ├─ 抖动量化 quantize8：把硬台阶换成随机颗粒（⚠ 当前实现有缺陷，见 ⑤）
│  └─ 不碰色度（default chroma=none）：避免制造新的色块
│
├─ ③ 常规暗图（输入均值 5~15，如 493 / 748 / LIME）
│  ├─ 只做：轻降噪 + 阴影补偿 + 抖动（+ 必要时去块）
│  ├─ 不改增益（台阶宽度仍是原来的 5~6 级）
│  ├─ 不动色度（色噪保留，但不会变成大色块）
│  ├─ 实测：平坦区亮度噪声 −12.5%~−18.8%，块效应 −3.5%~−4.5%
│  ├─ 下游：Canny 边缘精度 0.690→0.810（+17.5%），边缘数 −22%
│  └─ 代价：色噪 +9%，细节 std8 −13%（含噪声成分，不等于纹理丢失）
│
├─ ④ 极端暗光（输入均值<5，如 126 / 147 / 450）
│  ├─ 走"中性抬亮"：三通道同一 gamma 映射 → 绝对中性，不产生彩色斑
│  ├─ 逐像素判定：<3 全替换；3~12 线性羽化；>12 完全用模型输出
│  ├─ 目的：不再让模型把噪声/色噪放大成"彩色大斑"
│  └─ 代价：暗部变灰、细节减少、提亮幅度受限（126：2.9→22.9）
│
├─ ⑤ 抖动（dither）原理与现状
│  ├─ 目的：把"看得见的硬台阶"换成"看不见的随机颗粒"，平均亮度不变
│  ├─ 前提：必须作用在还有小数的浮点值上；幅度 >0.5 才能改变舍入结果
│  ├─ ⚠ 现状：代码先 .astype(uint8) 再抖 → dither=0.4 实测 0% 像素变化
│  ├─ 近黑分支（limit_dark_gain 输出浮点）抖动有效：26% 像素被改变
│  ├─ dither 0.9（幅度够大时）实测 59% 像素变化
│  └─ 若输出 16-bit PNG，则根本不需要抖动
│
└─ ⑥ 怎么证明有效 / 怎么表述
   ├─ 客观指标：平坦区色噪、块效应比、细节 std8、人造边界、梯度方向 cos
   ├─ 下游友好：边缘精度 / 召回 / 边缘像素数（vs 正常光 GT）
   ├─ 保真度：eval15 PSNR 15.86→15.77，SSIM 0.5584→0.5522（几乎不变）
   ├─ 可以说：假边缘减少、噪声下降、结构保持一致
   └─ 不能说：端到端抓取成功率提升（没做实验）
```

## 二、常规暗图 vs 极端暗光图：到底各做了什么

| 项目 | 常规暗图（均值 5~15） | 极端暗光（均值 <5） |
|---|---|---|
| 亮度降噪 | ✅ 轻量（NLM，20% 混合） | ✅ 同左 |
| 去块 | ⚠️ 仅块效应 >1.03 触发 | ⚠️ 同左 |
| 近黑限增益 | ❌ 不启用 | ✅ 启用（逐像素羽化） |
| 中性抬亮 | ❌ 不启用 | ✅ 启用（三通道同 gamma） |
| 色度处理 | ❌ 不碰（chroma=none） | ❌ 不碰（该分支走另一条路） |
| 阴影补偿 | ✅ 均值<15 时抬 4 级 | ✅ 同左 |
| 抖动 | ⚠️ 设计上有、当前实际几乎无效 | ✅ 在浮点上，部分生效 |
| 对"台阶"的作用 | 只能"少制造噪声 + 打散观感" | 直接把近黑压成中性，**真正降低放大倍数** |

**一句话区别**：常规暗图是"**不让噪声变成马赛克**"，极端暗光是"**承认没信息，干脆不放大、不变色**"。

## 三、抖动：为什么"整数上加 ±u"没用

- 输入是 8-bit 整数，但**抖动不是加在输入上**，而是加在"增强后、存 8-bit 之前"的浮点值上；
- 但我们的代码里，增强结果**先被 `.astype(np.uint8)` 转成整数**，再进 `quantize8(dither=0.4)`；
- 整数 + ±0.4 四舍五入必然回到原整数（|0.4|<0.5）→ **等于没做**（实测：493 上 0.000% 像素变化）；
- 要让抖动生效，必须：①在浮点上做；②幅度 > 0.5（常用 0.8~1.0）。

## 四、关于"抖动 → 放大 → 取整"循环的想法（分析）

设某像素增强前为整数 `x`，局部增益 `a`（暗区可达 5~6），输出理想值 `y = a·x`（浮点），最后一步量化 `round(y)`。

1. **只在输出端抖一次**：`round(a·x + u)`，`u~U(±0.5)`
   - 输出在相邻两档间随机跳（均值不变），**但**相邻平台的差是 `a·Δx`（Δx=1 时约 5~6 级）；
   - ±0.5 的抖动**改变不了 5~6 级的落差** → 平台边界依旧可见，只是内部变"花"。

2. **在输入端抖、让流水线帮忙放大**（其实就是你的想法里最有价值的那一半）：
   `round(a·(x+u)) = round(a·x + a·u)`
   - 抖动幅度被增益 `a` 放大：暗区 `a≈6` 时，输入 ±0.1 级 → 输出 ±0.6 级，**足以让量化结果随机化**；
   - 这就是"**在量化器之前注入抖动**"的正统做法（dithering），只是我们这个"量化器"在最末端，所以要在最前端注入、靠增益放大。

3. **循环多次（抖→放大→取整→再抖→再放大→再取整）**：
   - 第 `k` 轮的取整都会先把小数丢掉，再注入新噪声；
   - 数学上等价于：`round(...round(a·x + a·u₁) + a·u₂...)` → **每一轮都在累加噪声**，输出方差随轮数增加；
   - 平台的**平均值不变**（因为抖动零均值），所以"块与块之间的 5~6 级落差"仍在；
   - 结果：**块内部越来越花（颗粒变粗），块边界仍然在**；且每轮都丢精度，PSNR 单调下降，看起来像"多次压缩"。
   - 所以：**循环不是"把色块变成颗粒"的正确工具**，它只是"加更多噪声"。真正把色块边界变不显眼的只有三件事：降低放大倍数（限增益）、在边界处做空间过渡（掩盖）、或提高位深（从根上不产生台阶）。

4. **等价但更干净的做法（如果要做，我建议这个）**：
   - 先跑一次，得到浮点输出 `y` 和局部增益 `a ≈ y/x`；
   - 在**输入端**加抖动 `u = c · (1/a)`（c 取 0.5~1.0 级），让输出抖动恰好落在 ±0.5~1 级；
   - 再跑一次，取整输出 —— 一次完成，不需要循环；
   - 或者更简单：输出端抖一次，幅度 0.8~1.0；或直接 `--bit16`。

**结论**：你的直觉方向是对的（抖动应该在"被放大之前"加，让放大帮你把颗粒铺开），但"多次循环"不会提高效果，只会把噪声叠加、把画面弄脏。要做就用"增益补偿的输入域抖动"，一次即可。

## 五、常见误解清单（复习用）

| 误解 | 实际情况 |
|---|---|
| "马赛克是因为小数被磨掉了" | 小数被舍入是原因，但**视觉上主要是"成片平台 + 硬边界"**，误差本身 ≤0.5 级 |
| "存 PNG 就没马赛克了" | PNG 只去掉 JPEG 的 8×8 块和 4:2:0，**量化台阶与噪声放大照旧** |
| "放大倍数高一点没关系，后面再降噪" | 先放大后降噪 = 先把噪声抬到可见，再花更大力气抹掉，必然丢细节 |
| "抖动能把马赛克变回细节" | 抖动不产生信息，只改变量化误差的**空间分布** |
| "预处理越强越好" | 强平滑 = 大色块（E5/E9 的教训），所以我们改成"轻+不动色度" |
| "我们的方法能提升抓取成功率" | 只能说"假边缘减少、结构保持一致"，**没做端到端抓取实验** |
