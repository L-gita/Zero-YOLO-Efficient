> 本文档把“Zero-DCE 增强后出现马赛克/色块/偏色”这条线的**每一次尝试、每个数字、每次被证伪的方案**按时间顺序记下来，便于写论文/答辩时引用，也避免重复踩坑。

## 0. 一句话摘要

Zero-DCE 本身不含去噪/去马赛克能力，它把暗区的传感器噪声、8-bit 量化台阶、JPEG 块、色度噪声**一起放大 3.6~7.5 倍**，于是出现“马赛克”。
但我们**不能简单加一个“强降噪”**：实测重度色度平滑会把噪声抹成**几十像素级的大色斑**（比原来的马赛克更难看），还会把亮度细节砍掉一半、把天空磨成阶梯状色带。
最终采用的方案是：**只对亮度做轻度降噪 → 增强 → 只在“低信号平坦区”平滑色度 → 只有“几乎全黑”才做中性抬亮与抖动量化**（`--preprocess auto`，本文称 auto v3）。

---

## 1. 问题的五个来源（实测定位）

| 来源 | 说明 | 实测证据 |
| --- | --- | --- |
| ① 传感器噪声被放大 | 曲线 `LE(x)=x+α(x²−x)`，暗区斜率 `dy/dx = 1+α(2x−1) > 1`，噪声方差按斜率²放大 | 色度噪声 std 0.39→2.93（7.5×，126 极暗图）；平均梯度幅值放大 3.6~6.05× |
| ② 8-bit 量化台阶 | 极暗区只用到十几~三十几档灰度，增强后台阶被拉开 | 126_3_ 平均亮度 3.5、仅 37 档灰度；147_0_ 18 档 |
| ③ 增强曲线本身 | 逐通道独立映射，暗区对比度被放大，色度噪声也跟着涨 | 增强后 `M(输出)/M(输入)` 均值 5.47×（eval15） |
| ④ JPEG 8×8 块 | 仅低质量档明显；q85 以上在噪声里淹没 | 748：BMP/PNG/4:2:0/q85/q60 块效应比 0.98~1.06，差异在噪声量级内 |
| ⑤ 4:2:0 色度减半 | JPEG/MJPG 才有；YUYV 是 4:2:2；PNG 是 4:4:4 | 同一图存 PNG vs JPEG，色噪差异 ±15% |

**结论**：格式（JPEG/PNG/bag）只是帮凶之一，主因是 ①+②+③。
> bag 只是容器：里面 RGB 流是 YUYV（无损 4:2:2）还是 MJPG（相机内 JPEG）才决定有没有 8×8 块。

## 2. 时间线（含被证伪的方案）

### 2.1 `c909df6` 部署马赛克预处理（方案 B 第一版，E1~E5）

- 预处理四步：升位深（浮点处理）→ 色度优先降噪 → 8×8 去块 → 暗部轻抬；增强；保边平滑。
- 消融：E1 基线 / E2 先降噪→增强 / E3 增强→后降噪 / E4 弱降噪+平滑 / E5 全流程。
- eval15 数字（基线 E1 → E5）：色噪 12.18 → **1.08**，块效应比 1.004 → 0.882，M 放大 5.47× → 1.80×，PSNR 15.86 → 16.08，SSIM 0.5584 → 0.6573。
- **当时的结论（后来被推翻）**：“E5 综合最优”。

### 2.2 `5f13675` E5 被证伪 → 改用 E8 近黑区限增益

- 用户指出：E5 的极暗图**产生了更大的色块**、整体更糊。
- 量化诊断（新增 `chroma_plateau` 大色斑占比、`luma_std8` 细节）：
  - 126 极暗图：E1 大色斑 0.0011 → **E5 0.1564**（15.6% 整图变成一个色块）；
  - eval15：亮度细节 std8 11.91 → **5.53**（砍掉一半）；
  - eval15：色噪 12.18 → 1.08，但 `M` 放大 1.80× 是“抹平”换来的。
- **根因**：`chroma_denoise h=12` + `bilateral sigmaColor=12` 在近黑区把噪声抹成**大片均匀彩色斑块**；同时亮度被抹平。
- 新方案 E8：`neutral_lift`（三通道同一 gamma 的中性抬亮，避免彩色斑块）+ `limit_dark_gain`（近黑区用中性抬亮替代模型输出），同时加入 `chroma_guided_smooth`（亮度引导的色度平滑）。
- 大色斑：126 14.56% → **0.21%**；147 8.57% → 0.18%；748 2.51% → 0.58%；LIME 5.97% → 1.72%。

### 2.3 `1f1c86b` E8 的“硬灰块”问题 → E9（平滑亮度 + 羽化 + 抖动）

- 用户仍觉得 E8 与基线差别不大、甚至更差，且**出现大块灰块**。
- 量化根因：`limit_dark_gain v1` 直接拿 **8-bit 量化后的亮度**过 gamma → 输入只有几档 → 输出只有几档：
  - 126 图：**41.9% 像素落在灰度 0**、31.6% 落在 24/25 两档，相邻大面积色阶最大跳变 **24 级**（基线跳变 12 级）。
- 修法（E9）：先用大核 box 模糊把近黑区台阶抹成连续梯度（`smooth_radius=8`）再抬亮；掩码用 GaussianBlur 羽化；输出 8-bit 前加 ±0.6 级抖动（dither）。
- 结果（eval15）：条带跳变 E8 9.0 → **E9 2.8**（基线 2.5）；色噪 1.598；PSNR 16.02；SSIM 0.6754。
- 但 E9 仍有副作用：`prelift` 让输入分布偏移 → 748/威尼斯这类正常夜景发灰发淡；天空出现阶梯色带。

### 2.4 `d5181c1` E10：场景自适应（`--preprocess auto`）

- 思路：不再固定一条重管线，而是**按图决策**：
  - 噪声估计（暗区拉普拉斯残差 MAD/0.6745）→ 自适应降噪强度 `k = clip(σ/2, 0.35, 1.6)`；
  - 块效应估计（8×8 网格边界/非边界跳变比）→ 只有 >1.03 才去块；
  - 平均亮度 < 8 才轻抬。
- 后处理：只有很暗的图（均值 < 5）才走中性抬亮 + 抖动；否则只在平坦区平滑色度。
- 数字（E1 → E9 → auto）：126 色噪 1.35/0.73/1.00、细节 std8 4.01/3.03/**4.00**、条带 12/9/**4**；748 色噪 6.26/1.66/**3.00**、std8 14.73/8.24/**14.66**。

### 2.5 `3df3356`（auto v2）用户反馈“493 发黑、特征被淹没”

- 问题诊断：旧 auto 的 `limit_dark_luma` 把“暗但有纹理”的区域（493 左侧深色花纹布，输入亮度 3~12）当成无信号，整片替换成中性灰：
  - 暗区细节 std 8.07 → 5.85（−27%）；饱和度 158 → 136；σ 估计 5.93 → k 顶格 1.6 → 过度降噪。
- 改法 v2：不动亮度；只在“低信号平坦区”（局部均值 < 2σ 且局部 std < 0.7σ）平滑色度；补回色度幅度；只有均值 < 5 才走 E9 路径；新增 `--auto-strength`。

### 2.6 `d3cbbb3`（auto v3）用户反馈“493 整体偏绿、噪点多” + 大图 CUDA OOM

- **偏绿根因（Lab 实测）**：在**输入**上做色度降噪会让输出 `a*` 从 **+3.67 → −0.75**（绿移 4.4 个 Lab 单位）。
  原因：Zero-DCE 的曲线是**逐通道独立**的，输入亮度/色度一变，R/G/B 三通道增益就不同 → 颜色漂移。
  叠加因素：`_rescale_chroma` 末尾 `np.clip` 放大色度时的不对称截断。
- 改法 v3：
  1. 预处理**只对亮度降噪**（`luma_denoise`，NLM 只作用 Y，`h = 0.8 + 0.15k`），完全不碰输入色度；
  2. 色度降噪挪到**增强之后**、只作用于低信号平坦区，强度 `0.45k`，**不做色度回补**；
  3. 只有灰度均值 < 4 才轻抬，< 5 才走中性抬亮（正常夜景不再被替换成灰）；
  4. **>6 MP 的大图直接分块推理**（1024 块 + 128 重叠），修复对比工具 `12.14 GiB allocated → CUDA OOM`。
- 结果（原版 → auto v3）：

| 图 | 亮度 | 色度噪声 std | 亮度细节 std8 | 暗区条带跳变 |
| --- | --- | --- | --- | --- |
| eval15/493（玩偶+色卡） | 49.0 → 48.2 | 5.82 → **4.12** | 10.96 → 8.20 | 3 → 7 |
| eval15/748（羽毛球场） | 81.8 → 78.7 | 6.27 → **3.54** | 14.73 → 12.46 | 2 → 3 |
| real/126_3_（近黑） | 16.4 → 18.8 | 1.36 → **0.69** | 4.02 → 3.12 | **12 → 3** |
| LIME/1（威尼斯） | 95.4 → 94.9 | 3.35 → 3.31 | 11.78 → 10.60 | 3 → 3 |

> 493 的条带从 3 涨到 7：噪声原来把台阶“糊住”，降噪后台阶显形——这是“降噪 vs 条带”的固有矛盾，可用 `--auto-strength 0.5` 折中。

## 3. 最终方案（auto v3）与参数

**预处理（增强前）**
1. 块效应 > 1.03 才去块：亮度通道 8×8 网格边界 4 抽头平滑，只处理弱跨边界差以保真边缘；
2. 亮度 NLM 降噪：`h = 0.8 + 0.15k`（`k = clip(σ/2, 0.35, 1.6)`），**只作用 Y**；
3. 灰度均值 < 4 才 `prelift 0.08`。

**增强**：Zero-DCE（`snapshots_sice\Epoch50.pth`）。

**后处理（增强后）**
- 均值 < 5（几乎全黑）：亮度引导色度平滑 → 中性抬亮（`l0=3, l1=12, γ=0.55, strength=0.80`，羽化 + 抖动）；
- 否则：低信号平坦区色度平滑（`strength = 0.45k`，不回补色度）→ 8-bit 抖动量化。

**可调开关**：`--auto-strength`（0.5 更保守 / 1.3 更强）、`--preprocess light|mosaic|dark`、`--denoise/--deblock/--prelift/--post/--bit16`。

## 4. 指标定义与“踩过的指标坑”（写论文时要说明）

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 色度噪声 std | Cb/Cr 减去 5×5 模糊后的高频残差 std | 衡量彩色噪点 |
| 亮度细节 std8 | 8×8 块内灰度 std 的均值 | 细节保留（注意它也含噪声，不是纯“清晰度”） |
| 暗区条带跳变 | 输出图自身暗区里，占面积 >1% 的灰度级之间的最大跳变 | 衡量硬灰块/条带 |
| 暗区级数 | 暗区里占面积 >1% 的灰度级个数 | 越多越细腻 |
| 彩色块占比 | 色度幅度 ≥8 的连通块中最大者占全图比例 | 衡量“大色斑” |
| 块效应比 | 8×8 网格边界跳变 / 非边界跳变 | 衡量 JPEG 块 |

**最重要的教训**：8×8 块效应比**看不见 32 像素级的大色斑**。
E5 的块效应比从 1.004 降到 0.882（看起来更干净），但彩色块占比从 0.02 涨到 **0.15**、细节 std8 腰斩——**单一指标会给出反向结论**，必须“频域尺度”和“细节指标”一起看。

## 6. 与论文写作的对应

- **贡献点适合写成**：“面向低照增强的**终端侧预处理**（pre-processing）：在软件层模拟 ISP 的去噪与色调映射，抑制曲线增强对噪声/量化误差的放大”，而不是“Zero-DCE 能去噪”。
- **诚实边界**：预处理只能改善观感，**无法恢复**已被 ISP+8bit 量化+JPEG 丢掉的细节；极暗且彩色区域仍可能有残余色偏。
- **消融建议**：E1 基线 / E5 重度平滑（负面结果，用来证明“不能盲目强降噪”）/ E8 近黑限增益 / E9 抖动量化 / auto v3（最终）。
- **采集端建议**：固定机位多帧平均（5~10 帧，噪声降 √N）比任何后处理都有效，可作为“采集端贡献”单列。
